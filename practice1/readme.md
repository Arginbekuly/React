2.`Когда мы нажимаем на кнопку функция-обработчик попадает в Call Stack. 
Например при клике на "Run Load Users" вызывается taskUsers.run(). 
Внутри создается `Promise`, запускается `setTimeout`, и функция сразу вылетает из Call Stack. 
Стек снова свободен и может выполнять другой синхронный код.`

3.`setTimeout отдает сразу браузер.Браузер сам отсчитывает время на фоне.А основной поток JS работает дальше.Поэтому оно не блокирует.`

4.`=== START EVENT LOOP DEMO ===
Synchronous code (Call Stack)
Synchronous code end (Call Stack)
Promise .then() callback (Microtask)
setTimeout callback (Macrotask)
//Всё совпало 1 в 1.
Сначала выполнился весь синхронный код. Потом Event Loop сразу забрал микрозадачи из очереди (`Promise.then`). 
И только после них выполнил макрозадачу — колбэк из `setTimeout`.`

5.`
Микрозадачи выпоняется первыми и без очереди.
Макрозадачи наобарот выполняется по одному ожидая очереди.И начнет работать тогда когда микрозадачи стек пустой.
`

6.`
Запустили с помощью Promise.allSettled() потому что оно не как Promise.all.Если Promise.allSettled() работает без остановки даже при обнаружение ошибок оно продолжает дальше.
Тем временем promise.all остановливается при обнаружение первого Fail.Вот их различие`

7.`
Sequential это ожидание пока первый завершается и потом будет делать вторую задачу.И если мы сделаем 3 задачи на каждую потратить 1с тогда на все уходить 1с+1с+1с = 3с
Concurrent это когда все задачи работает одновременно не ожидая других. И оно потратить на 3 задачи около 1с - 1,5с`
