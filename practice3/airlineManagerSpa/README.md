# SkyLine Air — React Midterm

Учебная React SPA: каталог самолётов, конструктор моделей, касса, собственный/арендованный парк, техобслуживание и табло рейсов. Интерфейс выполнен на Tailwind CSS в стиле ретро-авиакассы.

- **Приложение:** https://skyline-air-midterm.vercel.app
- **Режим демонстрации ошибок:** https://skyline-air-midterm.vercel.app/?demo=1#catalog
- **Репозиторий:** https://github.com/Arginbekuly/React
- **Текущая версия:** локальная ветка `codex/skyline-midterm`. Push пока не подтверждён: GitHub отклонил старые учётные данные, а Git Credential Manager не завершил повторный вход после подтверждения на сайте.

## Запуск

Требуется Node.js 22.12+ (или актуальная поддерживаемая версия, совместимая с Vite 8).

```bash
cd practice3/airlineManagerSpa
npm ci
npm run dev
```

```bash
npm test          # 15 тестов simulated API
npm run lint     # ESLint, включая правила хуков
npm run build    # production-сборка в dist
npm run preview  # локальный просмотр production-сборки
npm run format   # форматирование исходников
```

Если терминал уже открыт в каталоге приложения, первый cd не нужен. Ориентируйтесь на URL, который напечатает Vite.

Стек: React 19, Vite 8, Tailwind CSS 4. Формы и состояние написаны без TypeScript, Redux, Context и UI-библиотек. Tailwind подключён через `@tailwindcss/vite`; повторяющиеся стили собраны через `@apply` в `src/index.css`. Manrope и Unbounded загружаются локально. В карточках каталога используются фотографии, в предпросмотре и отдельных секциях — inline SVG.

## Возможности

- 120 детерминированных начальных моделей с устойчивыми ID и числовыми номерами.
- Поиск по имени/номеру, фильтры по статусам приобретённых бортов, сортировки, пагинация 4/8/12.
- Список и детали: паспорт, цены, окупаемость, условная схема салона, похожие модели.
- Контролируемый конструктор: валидация, пять ливрей, live preview, асинхронное создание модели.
- Покупка, аренда, продажа/возврат; проверка баланса и лимита 60 бортов.
- Парк: локальная заметка, направление, фильтры, обратный порядок и сброс карточки через key.
- Рейсы: назначение, выбранный маршрут на SVG-карте, завершение и начисление дохода.
- ТО: износ, обслуживание, история, ангары и скидка до 40 %.
- Loading, error/retry, empty, success; блокировка повторной отправки и уведомления.
- Миграция старого сохранения без сброса баланса, пользовательских моделей и парка.

Это ручная учебная симуляция: рейс завершается кнопкой на табло, ТО — кнопкой на соответствующем экране. Завершение рейса даёт доход и +15 пунктов износа; плановое ТО убирает 50 пунктов и стоит 10 % цены со скидкой ангара. При 90 % износа новый рейс блокируется. Аренда завершается после 10 рейсов. Короткий маршрут в Талдыкорган (250 км) доступен даже моделям с минимальной дальностью 500 км.

## Единственный источник данных

`src/api/fakeApi.js` — simulated API. Все методы возвращают Promise с задержкой 300–600 мс, работают с JSON/localStorage и принимают AbortSignal. Компоненты не читают и не записывают localStorage напрямую.

| Метод | Назначение |
|---|---|
| `getGame({ signal })` | Снимок баланса, флота, ангаров, рейсов и журнала |
| `getAircraft({ search, status, sort, page, perPage, signal })` | Поиск/фильтры/сортировка/пагинация внутри API |
| `getAircraftById(id, { signal })` | Модель или null, плюс похожие модели |
| `createAircraft(data, options)` | Валидация, расчёт цен и создание модели |
| `acquire(id, rented, options)` | Покупка или аренда |
| `startFlight(id, destinationId, options)` | Назначение доступного борта на допустимый маршрут |
| `completeFlight(id, options)` | Однократное начисление дохода и изменение износа |
| `sell(id, options)` | Продажа или возврат аренды |
| `repair(id, options)`, `finishRepair(id, options)` | Начало и завершение ТО |
| `buyHangar(tier, options)` | Покупка ангара |

Команда возвращает обновлённый снимок `game`, сообщение и при необходимости созданную модель. Источник данных — сохранение API, а React хранит его отображаемый снимок. `data.js` содержит исходные справочники, фотографии и форматирование, `api/seed.js` — начальный набор и миграцию.

### Сохранение и миграция

Ключ: `skyline-air-redesign-v1`, версия схемы: 2. При первом запуске API создаёт 120 моделей. Старое сохранение дополняется отсутствующими исходными моделями; ID пользовательских моделей, баланс, флот, рейсы и журналы сохраняются. Пользовательские модели получают номера выше исходного диапазона; связанные номера бортов обновляются по modelId. Повторная загрузка не создаёт дубликатов.

localStorage привязан к origin/браузеру: сохранение localhost не переносится автоматически на публичный сайт, данные не синхронизируются между устройствами. Ошибка чтения/записи возвращается как ошибка API; приложение не сообщает об успешной операции до успешной записи. Исходное повреждённое сохранение автоматически не удаляется.

### Конкурентность и отмена

API читает актуальные данные внутри отложенной операции перед проверкой и записью. Поэтому две параллельные покупки проверяют актуальный баланс. Повторное завершение рейса не начисляет доход второй раз. Ответы — JSON-копии, изменение ответа не меняет сохранение.

AbortSignal очищает таймер, отклоняет Promise с AbortError и не выполняет отменённую операцию. React-эффекты отменяют устаревшую загрузку в cleanup и проверяют signal перед обновлением state. Глобальная команда дополнительно блокируется ref до следующего render, чтобы двойной клик не запускал два действия.

## Как это работает

### Состояние и props

Общее состояние авиакомпании хранится в `useAirline`, который вызван один раз в App. Поиск и пагинация живут в Catalog; поля формы — в AircraftForm; заметка/направление — в FleetCard; выбранный рейс — в FlightsPage. App передаёт данные вниз через props и передаёт обработчики действий. Все изменения массивов выполняются иммутабельно через spread, map и filter.

### Эффекты и cleanup

| Место | Зависимости | Работа и очистка |
|---|---|---|
| `useAirline` | `retryKey` | Загрузка общего снимка; отмена загрузки/команды при unmount |
| `Catalog` | `requestKey` | Ключ содержит поиск после debounce, фильтр, сортировку, страницу, perPage, revision, retry, simulateError; отмена предыдущего запроса |
| `AircraftPage` | `requestKey` | Ключ содержит ID, revision, retry и simulateError; отмена при смене параметров/unmount |
| `useDebounce` | `value`, `delay` | Таймер поиска; clearTimeout в cleanup |
| `Toast` | `notice`, `onClose` | Закрытие через 5 с; clearTimeout в cleanup |
| `App` | `[]` | Подписка на hashchange; removeEventListener в cleanup |

Loading определяется несовпадением ключа полученного ответа с текущим ключом запроса. Старые карточки не выдаются за ответ нового запроса. Отменённые запросы не показываются как ошибки. Это защищает от race condition при быстром поиске и переходах.

### Identity, keys и локальные поля

Модели, борты и рейсы используют устойчивые ID. При изменении порядка карточки сохраняют свои локальные поля. Ключ карточки парка включает версию сброса: смена версии пересоздаёт конкретную карточку и сбрасывает заметку/направление. При исключении карточки фильтром она размонтируется и теряет локальные поля — это осознанное поведение.

Главная скрывается при переходе на другой экран, сохраняя форму/каталог. Детали получают `key={id}`. Номера моделей используются для отображения, ID — для идентичности и связей.

### Render, commit, batching и closures

Render вычисляет дерево из props/state, commit применяет изменения к DOM. Изменение заметки обновляет локальную карточку; изменение снимка авиакомпании обновляет App. Несколько обновлений React может объединять в один render. Обработчик видит snapshot своего render; функциональное обновление `setRetryKey(value => value + 1)` использует предыдущее актуальное значение.

Эффект захватывает параметры запроса через closure. Cleanup отменяет прежний запрос, чтобы его более поздний ответ не заменил актуальный. Деньги и доступность борта проверяются API по сохранению, а не по устаревшему снимку из React.

### Навигация

Используются hash-маршруты: `#catalog`, `#build`, `#fleet`, `#aircraft/1`, `#maintenance`, `#flights`. Работают история браузера и перезагрузка выбранных деталей. Серверные rewrite-правила и React Router для этого не нужны. Неизвестный ID показывает «Борт не найден».

## Как проверить состояния

Откройте `/?demo=1#catalog` — только в этом режиме появляются инструменты проверки для защиты:

1. «Показать загрузку» — повторный запрос каталога.
2. «Сымитировать ошибку каталога» — после задержки появляется ошибка; «Повторить» восстанавливает загрузку.
3. В деталях доступна кнопка ошибки деталей.
4. В форме есть checkbox ошибки сохранения: поля сохраняются после ошибки; снимите checkbox и повторите отправку.
5. Невозможный поиск показывает empty, `#aircraft/no-such-id` — отсутствующую модель.
6. Быстро меняйте поиск/фильтр — устаревшие запросы отменяются.

В обычном режиме случайных сбоев нет. Успехи и ошибки бизнес-операций показываются через Toast; форма также имеет собственные сообщения.

## Деплой и сдача

Приложение опубликовано на Vercel. В `vercel.json` заданы Vite, `npm run build` и `dist`. При импорте всего GitHub-репозитория укажите **Root Directory: `practice3/airlineManagerSpa`**. CLI из каталога приложения: `vercel deploy --prod` после `vercel login`.

Отдельный backend не требуется: simulated API работает в браузере. `.vercel`, `.env`, node_modules и dist не коммитятся. Автоматический деплой из GitHub отдельно не настроен; текущая публикация выполнена CLI.

Перед сдачей автору нужно пройти ручные сценарии из чек-листа, отрепетировать защиту, приложить ссылки на GitHub и публичное приложение и нажать **Turn in до дедлайна**. Само наличие репозитория/деплоя не отправляет задание в учебную систему.
